你的 AI 已经会写代码，现在把设计规则也交给它。

技能就是纯 markdown 文件，规则即产品。

缺失的那一块

代码能编译，设计不能。

AI 编码工具交付的功能总能跑起来，配的却是千篇一律的布局、随手借来的字体和毫无道理的间距。要一个落地页，它还你一个页面；要一个好的落地页，它还你模型记得的那个。

差距从来不在代码，而在模型能遵循的设计系统。这些技能把这样一套系统放进你的工具里，一次一个 markdown 文件。

你会得到什么

两个技能，一套工作方式。

每个技能自成一个文件夹，核心只有一个 SKILL.md。按需安装。

页面会说话，不只是渲染

landing-page-design 先问清楚再画像素：先定页面结构，再写转化文案，最后才是视觉系统，顺序不乱。产出自带任务。

真正能动手改的 Figma 文件

figma-designer 搭建真实结构：间距、圆角、颜色变量、命名文字样式、自动布局、含全部状态的组件，以及一个跟踪设计令牌的 Foundations 画板。

一个技能一个文件，各工具通用

Claude Code、Cursor、Codex、Windsurf、Cline 读的都是同一份 markdown。无需迁移，换编辑器也不用重写。

拿去就能改

所有设计取值——字体、颜色、间距、圆角、动效——都集中在每个文件底部的一节里。fork 仓库、改那一节，技能其余部分随之适配。

用法

安装，提问，交付。

STEP 01

安装

运行一条 npx 命令，选好技能和要启用的 agent。技能装进 .claude/skills/ 或 .agents/skills/。

STEP 02

用大白话提需求

「给我的应用做个落地页。」intake、结构、文案、视觉系统都交给技能。你审结果，不用审规则。

STEP 03

先交付，后更新

产出自始至终遵循同一套设计系统。之后运行 npx skills update 拉取仓库更新。

常见问题

有问题，直说答案。

这就是一堆提示词吗？

不是。每个技能就是一份 markdown 规则文件，分两半：策略部分决定页面说什么，视觉系统决定页面长什么样。模型遵循的是文件，不是感觉。

支持哪些工具？

任何能读 markdown 规则文件的工具：Claude Code、Cursor、Codex、Windsurf、Cline。在 Claude.ai 上，下载 SKILL.md，上传到 Project 或挂在对话里即可。

必须两个技能都装吗？

不用，按需装：npx skills add elayadesign/ai-design-skills --skill landing-page-design。

设计取值能改吗？

能。字体、颜色、间距、圆角、动效都在每个文件底部的一节里。fork 仓库、改那一节，技能其余部分自动适配。

站点已经存在怎么办？

用配套技能 redesign-skill。它诊断现有站点，所有具体取值都遵从这套规则。

能审计线上页面吗？

SlopScan 用同一套规则检查线上页面，并把修复提示交给你的 agent。

需要账号吗？会外传数据吗？

不需要账号。技能就是你项目里的本地 markdown 文件。仓库本身跑 CI，每次推送校验每个 SKILL.md。

用什么许可证？

MIT。随便用、随便 fork、用它做的东西直接发布，无需署名。
