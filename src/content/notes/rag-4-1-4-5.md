# 模块 4 RAG 知识点整理

## 一、知识点整理

### 1. RAG 两阶段：离线建库 + 在线问答

**讲解**：  
RAG 分两个阶段，职责完全不同。

- **离线建库**：跑一次，把文档变成向量库
- **在线问答**：每次请求，检索 + 生成

```text
离线建库（跑一次）：
PDF → Loader → Splitter → Embedding → Vector Store

在线问答（每次请求）：
用户问题 → Embedding → 检索 Top-K → 填充 Prompt → LLM → 答案
```

**核心概念**：

| 概念 | 作用 |
|---|---|
| Loader | 加载 PDF/Word/HTML |
| Splitter | 切分成 chunk |
| Embedding | 文本转向量 |
| Vector Store | 存向量，支持相似检索 |
| Retriever | 从向量库检索片段 |
| Reranker | 重排结果（未用） |

**效果**：  
建库一次，检索无数次。日常调优重点在检索参数和 Prompt，不在重建库。

---

### 2. 文档加载：PyPDFLoader

**讲解**：  
用 `PyPDFLoader` 加载 PDF，返回 `list[Document]`。  
每个 `Document` 有 `page_content` 和 `metadata`（含页码、来源）。

**代码**：

```python
# app/rag/loader.py
from pathlib import Path
from langchain_community.document_loaders import PyPDFLoader

def load_pdf(pdf_path: str | Path):
    loader = PyPDFLoader(str(pdf_path))
    return loader.load()
```

**关键字 / 导入包**：

- `PyPDFLoader`：`from langchain_community.document_loaders import PyPDFLoader`
- `loader.load()` 返回 `list[Document]`
- `Document.page_content` / `Document.metadata`

**效果**：  
PDF 文本被提取成 `Document` 列表，后续可切分、嵌入。

**注意**：  
`PyPDFLoader` 只提取文本，**不访问网址**。PDF 里的网址只是字符串。

### 3. 文本切分：RecursiveCharacterTextSplitter

**讲解**：  
把长文档切成 chunk。  
`RecursiveCharacterTextSplitter` 优先按分隔符切，保证语义完整。  
中文要加 `。！？` 分隔符。

**代码**：

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,
    chunk_overlap=50,
    separators=["\n\n", "\n", "。", "！", "？", " ", ""],
)
chunks = splitter.split_documents(documents)
```

**参数详解**：

| 参数 | 作用 | 建议 |
|---|---|---|
| `chunk_size` | 每块字符数 | 500-800 |
| `chunk_overlap` | 相邻块重叠 | chunk_size 的 10%-20% |
| `separators` | 切分优先级 | 中文加 `。！？` |

**关键字 / 导入包**：

- `RecursiveCharacterTextSplitter`：`from langchain_text_splitters import RecursiveCharacterTextSplitter`
- `split_documents(documents)`

**效果**：  
长文档被切成 500 字左右的 chunk，相邻块有 50 字重叠，语义不丢。

**注意**：

- `overlap` 是**上限**，实际重叠取决于切点，不要追求精确等于
- 验证参数要看**块长度**和**相邻块边界**，不要只看第一块开头

**验证代码**：

```python
print(len(chunks[0].page_content))

tail = chunks[0].page_content[-150:]
head = chunks[1].page_content[:150]
```

### 4. Embedding 选型：API vs 本地

**讲解**：  
Embedding 把文本转向量，是 RAG 的核心。  
两种模式：API 和本地 GPU。选型看资源约束，不只看速度。

| 模式 | 模型 | 优势 | 劣势 |
|---|---|---|---|
| **API** | 硅基流动 `BAAI/bge-m3` | 免费、零存储、上线一致 | 网络延迟 |
| 本地 GPU | `BAAI/bge-m3` | 极快 | 占 5G+ 存储、2-3G 内存 |

**代码**：

```python
# app/rag/embeddings.py
import os
from langchain_openai import OpenAIEmbeddings

def get_embeddings():
    return OpenAIEmbeddings(
        model="BAAI/bge-m3",
        api_key=os.getenv("SILICONFLOW_API_KEY"),
        base_url="https://api.siliconflow.cn/v1",
        check_embedding_ctx_length=False,
    )
```

**关键字 / 导入包**：

- `OpenAIEmbeddings`：`from langchain_openai import OpenAIEmbeddings`
- `model="BAAI/bge-m3"`
- `base_url`
- `check_embedding_ctx_length=False`：非 OpenAI 端点必须关

**效果**：  
API 模式零存储、上线一致，适合存储和内存紧张的环境。

**注意**：

- `pip install torch` 默认装 CPU 版，本地 GPU 要用官方 CUDA 命令重装
- 技术选型要看资源，API 免费时没理由用本地

### 5. 向量库：Chroma 构建与加载

**讲解**：  
Chroma 是轻量本地向量库，支持持久化。  
`from_documents` 一步完成嵌入 + 存储。  
重启后用 `Chroma(...)` 加载，不用重建。

**代码**：

```python
# app/rag/vectorstore.py
from pathlib import Path
from langchain_chroma import Chroma
from app.rag.embeddings import get_embeddings

CHROMA_DIR = Path("chroma_db")


def build_vectorstore(chunks):
    embeddings = get_embeddings()
    return Chroma.from_documents(
        documents=chunks,
        embedding=embeddings,
        persist_directory=str(CHROMA_DIR),
    )


def load_vectorstore():
    embeddings = get_embeddings()
    return Chroma(
        persist_directory=str(CHROMA_DIR),
        embedding_function=embeddings,
    )
```

**关键字 / 导入包**：

- `Chroma`：`from langchain_chroma import Chroma`
- `from_documents(documents, embedding, persist_directory)`
- `Chroma(persist_directory, embedding_function)`

**效果**：

- `from_documents` 一步完成嵌入 + 存储
- `persist_directory` 持久化，重启不丢
- 用 `force_rebuild` 控制重建 vs 加载

### 6. 检索参数：MMR

**讲解**：  
检索质量直接决定 RAG 效果。  
MMR（最大边际相关）兼顾相关性和多样性，避免返回多条几乎相同的片段。

**代码**：

```python
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={
        "k": 4,
        "fetch_k": 20,
        "lambda_mult": 0.5,
    },
)
```

**参数详解**：

| 参数 | 作用 | 常用值 |
|---|---|---|
| `k` | Top-K | 4 |
| `search_type` | 检索策略 | `mmr` |
| `fetch_k` | MMR 候选数 | 20 |
| `lambda_mult` | 相关性/多样性平衡 | 0.5 |
| `score_threshold` | 相似度阈值 | 0.4 |

**关键字 / 导入包**：

- `vectorstore.as_retriever(...)`
- `search_type="mmr"`
- `search_kwargs`

**效果**：  
返回 4 条覆盖多角度的片段，不是 4 条重复内容。  
`score_threshold=0.4` 过滤低相似度结果，避免瞎答。

### 7. RAG 链：并行填充 context + question

**讲解**：  
用 `{...}` 并行填充，把同一输入分发到多个分支。  
`RunnablePassthrough` 原样传递，`RunnableLambda(format_docs)` 把 `list[Document]` 拼成字符串。

**代码**：

```python
# app/rag/chain.py
from langchain_core.runnables import RunnableLambda, RunnablePassthrough
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

from app.llm.client import get_llm
from app.rag.vectorstore import load_vectorstore

RAG_PROMPT = ChatPromptTemplate.from_messages([
    ("system",
     "你是智能客服助手，语气友好、专业、自然。\n"
     "规则：\n"
     "1. 用你自己的话组织答案，不要照抄原文。\n"
     "2. 可以结合多个片段，给出有条理的建议。\n"
     "3. 如果片段中没有相关信息，回答"
     "\"抱歉，暂时没有找到相关资料\"。\n"
     "4. 回答控制在 200 字以内。\n"
     "5. 结尾标注来源页码，格式：[来源：第X页]"),
    ("human", "知识片段：\n{context}\n\n用户问题：{question}"),
])


def format_docs(docs):
    return "\n\n".join(
        f"[第{d.metadata.get('page', '?')}页] {d.page_content}"
        for d in docs
    )


def safe_format_docs(docs):
    if not docs:
        return "（无相关知识片段）"
    return format_docs(docs)


def build_rag_chain():
    vectorstore = load_vectorstore()
    retriever = vectorstore.as_retriever(
        search_type="mmr",
        search_kwargs={"k": 4, "fetch_k": 20, "lambda_mult": 0.5},
    )

    return (
        {
            "context": retriever | RunnableLambda(safe_format_docs),
            "question": RunnablePassthrough(),
        }
        | RAG_PROMPT
        | get_llm()
        | StrOutputParser()
    )


rag_chain = build_rag_chain()
```

**关键字 / 导入包**：

- `{...}` 并行填充
- `RunnablePassthrough` / `RunnableLambda`
- `retriever | RunnableLambda(safe_format_docs)`
- `StrOutputParser`

**效果**：

```text
输入 "退款政策是什么？"
  ├── 分支1：retriever 检索 → safe_format_docs → context
  └── 分支2：RunnablePassthrough → question
  → prompt 填充 → llm → parser → 答案
```

### 8. RAG Prompt 设计

**讲解**：  
Prompt 措辞决定输出风格。"只使用"和"基于"效果完全不同。

**代码**：

```text
你是智能客服助手，语气友好、专业、自然。
规则：
1. 用你自己的话组织答案，不要照抄原文。
2. 可以结合多个片段，给出有条理的建议。
3. 如果片段中没有相关信息，回答"抱歉，暂时没有找到相关资料"。
4. 回答控制在 200 字以内。
5. 结尾标注来源页码，格式：[来源：第X页]
```

**要点**：

- "用自己话组织" → 避免机械照抄
- 明确兜底话术 → 无相关知识不瞎编
- 要求标注来源 → 可追溯
- 限制字数 → 控制 token

**效果**：  
回答自然、有条理、带来源，不会像念文档。

### 9. 集成到智能客服：意图扩展 + 路由

**讲解**：  
意图从 3 类扩展到 4 类，加 `knowledge`。  
路由顺序：order → refund → knowledge → general。  
RAG 链要 string 输入，路由字典要包装。

**代码**：

```python
# app/llm/parsers.py
class Intent(BaseModel):
    intent: Literal["refund", "order", "knowledge", "general"] = Field(
        ..., description="用户意图"
    )
    order_id: int | None = Field(None, description="订单号")


# app/llm/router.py
from langchain_core.runnables import RunnableLambda, RunnableBranch
from app.rag.chain import rag_chain
from app.llm.tools import query_order, create_refund

# RAG 链要 string 输入，包一层从字典里取 question
knowledge_chain = RunnableLambda(lambda x: x["question"]) | rag_chain

router = RunnableBranch(
    (lambda x: x["intent"] == "order", order_chain),
    (lambda x: x["intent"] == "refund", refund_chain),
    (lambda x: x["intent"] == "knowledge", knowledge_chain),
    general_chain,
)
```

**关键字 / 导入包**：

- `Literal["refund", "order", "knowledge", "general"]`
- `RunnableLambda(lambda x: x["question"]) | rag_chain`
- `RunnableBranch`

**效果**：  
四种意图全部跑通，知识类问题走 RAG，带来源回答。

**注意**：  
链的输入类型要匹配。router 传字典，RAG 链要字符串，用 `RunnableLambda` 转换。

### 10. 双重兜底：score_threshold + Prompt

**讲解**：  
无关问题（如"今天天气"）不能瞎答。  
两层兜底：代码层过滤低相似度，Prompt 层兜底话术。

**代码**：

```python
# 代码层：score_threshold 过滤
retriever = vectorstore.as_retriever(
    search_type="mmr",
    search_kwargs={
        "k": 4,
        "fetch_k": 20,
        "lambda_mult": 0.5,
        "score_threshold": 0.4,
    },
)


# Prompt 层：空 context 兜底
def safe_format_docs(docs):
    if not docs:
        return "（无相关知识片段）"
    return format_docs(docs)
```

**关键字**：

- `score_threshold=0.4`
- `safe_format_docs`
- Prompt 里 "如果片段中没有相关信息，回答……"

**效果**：  
低相似度直接返回空，Prompt 兜底话术让模型不瞎编。

## 二、踩坑点速查

| 坑 | 原因 | 解决 |
|---|---|---|
| PyTorch 是 CPU 版 | `pip install torch` 默认 CPU | 用官方 CUDA 命令重装 |
| Embedding 选型纠结 | 本地快但占资源 | 看资源约束，API 免费就用 API |
| chunk 参数验证方法错 | 只看第一块开头 | 看块长度和相邻块边界 |
| overlap 实际值 ≠ 配置值 | 切点不精确 | 配置值是上限，不追求精确 |
| 回答太机械 | Prompt "只使用"被理解成"照抄" | 改成"用自己话组织" |
| 网址无法查看内容 | PyPDFLoader 不访问网址 | WebBaseLoader 抓取，或只输出链接 |
| 无关问题瞎答 | 无兜底 | score_threshold + Prompt 兜底 |
| RAG 链输入类型不匹配 | router 传字典，RAG 要字符串 | `RunnableLambda` 包装转换 |

**核心教训**：

1. **技术选型看资源约束**，不只看速度
2. **参数验证看边界和相邻关系**，不看开头
3. **Prompt 措辞决定输出风格**
4. **双重兜底**：代码层 + Prompt 层
5. **输入类型要匹配**，不匹配就包装
6. **LangSmith 是神器**，检索了什么、context 填了什么，一看便知

## 四、测试用例 `test_rag.py`

```python
import pytest
from unittest.mock import patch, MagicMock
from langchain_core.documents import Document

from app.rag.chain import format_docs, safe_format_docs


# ==================== 文档格式化 ====================
def test_format_docs():
    docs = [
        Document(page_content="退款政策是7天无理由。", metadata={"page": 1}),
        Document(page_content="超过7天需联系客服。", metadata={"page": 2}),
    ]
    result = format_docs(docs)
    assert "[第1页]" in result
    assert "[第2页]" in result
    assert "退款政策" in result


def test_format_docs_missing_page():
    docs = [Document(page_content="内容", metadata={})]
    result = format_docs(docs)
    assert "[第?页]" in result


def test_safe_format_docs_empty():
    assert safe_format_docs([]) == "（无相关知识片段）"


def test_safe_format_docs_non_empty():
    docs = [Document(page_content="内容", metadata={"page": 1})]
    result = safe_format_docs(docs)
    assert "内容" in result
    assert "无相关知识片段" not in result


# ==================== 切分 ====================
def test_split_documents():
    from langchain_core.documents import Document
    from langchain_text_splitters import RecursiveCharacterTextSplitter

    splitter = RecursiveCharacterTextSplitter(
        chunk_size=50,
        chunk_overlap=10,
        separators=["\n\n", "\n", "。", "！", "？", " ", ""],
    )

    long_text = "这是第一句。这是第二句。这是第三句。" * 10

def test_split_overlap_boundary():
    from langchain_core.documents import Document
    from langchain_text_splitters import RecursiveCharacterTextSplitter

    splitter = RecursiveCharacterTextSplitter(
        chunk_size=50,
        chunk_overlap=10,
        separators=["。", ""],
    )

    text = "第一句话。" * 10
    chunks = splitter.split_documents(
        [Document(page_content=text, metadata={"page": 1})]
    )
    # 相邻块应有重叠
    if len(chunks) >= 2:
        tail = chunks[0].page_content[-5:]
        head = chunks[1].page_content[:10]
        # 不强制精确，但验证相邻关系存在
        assert tail or head
```

## 五、总结串联关系

1. **离线建库**：`PyPDFLoader` 加载 → `RecursiveCharacterTextSplitter` 切分 → `Embedding` 嵌入 → `Chroma` 存储。
2. **在线问答**：问题嵌入 → MMR 检索 Top-4 → `safe_format_docs` 拼 context → Prompt → LLM → 答案。
3. **检索参数**：`k=4`、`search_type="mmr"`、`fetch_k=20`、`lambda_mult=0.5`、`score_threshold=0.4`。
4. **RAG 链**：`{context, question}` 并行填充 → Prompt → LLM → Parser。
5. **意图扩展**：`Literal` 加 `knowledge`。
6. **路由**：`RunnableBranch` 加 knowledge 分支，`RunnableLambda` 包装字典转字符串。
7. **双重兜底**：`score_threshold` 过滤 + Prompt 兜底话术。
8. **Prompt 措辞**：用自己话组织、标注来源、限制字数。

**一句话串起来**：  
`Loader` 加载 → `Splitter` 切分 → `Embedding` 嵌入 → `Chroma` 存储 → `Retriever` 检索 → `safe_format_docs` 拼 context → `Prompt` 约束 → `LLM` 生成 → `RunnableBranch` 按意图路由。

这就是模块 4 RAG 的全部骨架。你的智能客服现在能基于公司文档回答，带来源标注，无关问题不瞎编。下一步模块 5 记忆系统会让它跨会话记住用户。
