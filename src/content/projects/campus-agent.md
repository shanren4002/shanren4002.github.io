## 项目简介

校园场景 AI 对话助手，毕业设计项目。基于 FastAPI + LangChain，按 Phase 分阶段演进：从单轮对话开始，逐阶段叠加多轮上下文、消息持久化、长期记忆，最终完成记忆管理页面与「记忆B」匹配档案，五个阶段全部交付。

## 核心能力

- **模拟认证**：学号 + 验证码登录（验证码落在后端终端窗口），会话 token 管理，重启失效、聊天记录从磁盘自动恢复
- **消息持久化**：会话级 JSON 文件存储，旧版全局文件已通过迁移脚本升级到按会话分文件
- **长期记忆（记忆A）**：登录时初始化用户基础档案，跨会话检索 active traits 并在首次缺失的会话中凝练注入；支持证据升级、reflection 衰减与容量淘汰
- **记忆管理页 + 记忆B（匹配档案）**：按「校园招聘网申档案」模板填写技能、项目与合作意向，基本信息由学籍信息自动带入且只读；提交后由 dispatcher 双路分发——路径A 按规则更新记忆A，路径B 生成匹配档案
- **冲突裁决显式化**：A 层页面提交让位于对话观察（聊天体验以实时对话为准），B 层页面提交覆盖对话派生值（匹配以用户主动声明为准）；任一路 LLM 失败只影响该路并记日志
- **设计令牌纪律**：`tokens.css` 为唯一色源，组件样式禁止硬编码颜色（有测试看守），四档圆角、双字体分工，2026-10-29 视觉层重构只换视觉、DOM 与 API 契约零改动

## 技术架构

FastAPI 分层架构：`api`（HTTP 层）/ `agent`（编排与提示词）/ `llm`（模型封装）/ `schemas`（数据模型）/ `core`（配置日志错误码）/ `auth`（模拟认证）/ `memory`（长期记忆与双路分发）/ `storage`（持久化）。前端为 templates + 原生 JS 三页面（登录 / 对话 / 记忆管理），默认模型 deepseek-chat。pytest 全量 143 passed，全部使用假配置，离线可跑。

## 复盘

这个项目最完整的实践是「分阶段交付」：每个 Phase 有独立任务书，一次只读当前阶段；视觉重构严格限定在视觉层，功能与信息架构不动。而双路分发 + 冲突裁决的设计说明一件事：当 AI 提取和用户声明两个信息源并存时，「谁让位谁」必须写成显式规则，而不是留给模型临场发挥。
